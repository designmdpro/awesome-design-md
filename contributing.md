# Contribution Guidelines

Thanks for helping keep this list useful. Please read this before opening a pull request.

## What belongs here

An entry should be about DESIGN.md itself: the spec, files in the format, or a tool, skill or server that reads or writes it. General design-system resources belong in other lists.

To be accepted, a project should:

- Work today and be maintained. No archived repositories, dead links or "coming soon" pages.
- Have a README or docs that explain what it does and how to use it.
- Produce or consume real DESIGN.md files. Tools that only mention the format in passing are out of scope.
- Be useful to people other than its author. Personal experiments with no documentation will be declined.

Commercial projects are welcome if they offer something usable for free. Paid-only products are not listed.

## Entry format

```md
- [Name](https://link) - Short description that ends with a period.
```

- Add the entry at the bottom of the right section.
- Keep the description to one sentence. Say what it does, not how good it is.
- Use the project's own capitalization (Node.js, not NodeJS).
- One entry per pull request, so each one can be reviewed on its own.

If you maintain the project you are adding, say so in the pull request.

## Files in `design-md/`

The `design-md/` folder is synced automatically from DesignMD Pro and is not edited by hand. To report a wrong color, token or description in one of those files, open an issue and include the file path and the value you believe is correct.

## Disclosure

This list is maintained by the people behind DesignMD Pro. Entries for DesignMD Pro are marked in their descriptions, and other projects are judged by the same rules as ours.
